# Testing

## Automated checks

| Check | Command | What it covers |
| --- | --- | --- |
| Documents | `node --test tests/documents.test.mjs` | Actual PDF.js extraction and CSV parsing of all 100 files; 30 verified/20 unverified per format; matching evidence; normalization, missing values and public-report filtering |
| Assistant | `node --test tests/assistant.test.mjs` | Mocked Google requests; secret header placement; bounded output; summary allowlist; sanitized errors |
| Interface | `node --test tests/interface.test.mjs` | Simulated DOM; main navigation, phone-width toggle, all nine tour steps and safe AI text rendering |
| TypeScript | `pnpm exec tsc --noEmit` | Type checking |
| Worker integration | `node scripts/test-server.mjs` after build | Isolated D1, seeding 500 records, API search/comparison, 30/20 outcomes, quota enforcement, cross-origin rejection, private-report filtering and failure on partial dataset |

`public/downloads/test-report.json` records the document test results and is regenerated by the document suite. The 50-case manifest is for validation only.

## Manual checks still needed

Real-device PDF/CSV uploads, layout screenshots, keyboard/screen-reader behavior, Bangla voice availability, scanned handwriting and a fresh external-machine setup need manual browser verification. Happy DOM tests do not establish real rendering or device compatibility. Google responses can vary and are not a legal source of truth.
